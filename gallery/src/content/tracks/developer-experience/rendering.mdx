## Profile a React interaction

Choose a slow interaction you can reproduce: typing, opening a panel or selecting an item. The goal is to find the work behind it and evaluate one change—not to eliminate renders.

### Record and investigate

Use [React Developer Tools](https://react.dev/learn/react-developer-tools) to record the interaction in Profiler. Inspect its commit in the flamegraph or ranked view, then examine the relevant props and state. Repeat to avoid mistaking startup work for the problem.

Need an example? <DemoLink id="react-render-detective">React Render Detective</DemoLink> demonstrates updates with deliberately cheap tiles. Its counters aren't speed measurements. Compare `experiment.tsx` and `tile.tsx` under `demos/react-render-detective/`.

Follow the state update and ask:

- Is state higher in the tree than necessary?
- Are objects or callbacks recreated for each render?
- Is expensive work repeated with unchanged inputs?

Stable props help a memoised component skip parent-driven updates; its own state and context can still cause updates.

### Change one thing and compare

Choose a change supported by the recording. Preserve behaviour, then repeat with the same data and environment. Remove the change if it doesn't help; don't add memoisation everywhere.

Development checks and profiling add overhead. Use the browser Performance panel to investigate scripting, layout and painting beyond React. Fewer commits alone don't prove a faster interaction.

Read [React memo](https://react.dev/reference/react/memo) and [Chrome Performance](https://developer.chrome.com/docs/devtools/performance). If computation dominates, explore a [Web Worker](#/track/modern-web/workers).
