## Make one agent task repeatable

**Would the same request produce an equally useful result tomorrow?** Choose a small task whose result you can check: tracing a dependency, reviewing a diff or selecting relevant tests.

Use Codex or Copilot CLI if you already have access. You can also write and evaluate the instructions manually; this experiment does not require an account or a new installation.

### Compare a prompt with a skill

Try the task once with a short request. Record which files, checks and assumptions the agent used. Then create a local draft at `.agents/skills/review-one-change/SKILL.md`:

```md
---
name: review-one-change
description: Review a specified local diff for a concrete regression. Use when asked to review one change without editing it.
---

1. Identify the requested diff and read the affected callers.
2. Follow one changed behaviour from input to result.
3. Find a realistic failure case; check whether an existing test covers it.
4. Report the location, impact and evidence. Separate confirmed findings from questions.
5. Do not edit files, commit, push or change permissions.
```

Ask your tool to use the named skill on the **same diff**, following its discovery instructions. Verify that it loaded the skill rather than assuming a named file was used. This repository's `.agents/skills/lab-debugging/SKILL.md` is another small example to inspect.

### Choose a direction

- **Reusable investigation:** adapt the draft to tracing one dependency. Check its claims against imports and the lockfile.
- **Assisted implementation:** request one small change in your working copy, inspect the patch and run the relevant existing test. Keep committing a separate decision.
- **Repeatable review:** run the same review against a known mistake and a correct change. Did it find the mistake without inventing one in the correct version?

An optional stretch is a script that runs a deterministic check before the agent interprets its output. Keep observed results separate from the agent's explanation; “looks fine” is not a test result.

Compare the effort, useful findings and missed details between the two runs. Keep instructions that improve the result, and remove rules that only produce more text.

See [Codex skills](https://learn.chatgpt.com/docs/build-skills) and [Copilot CLI skills](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills) for discovery and invocation. Both support repository skills in `.agents/skills`; keep a single copy when trying the two tools. Review downloaded skills before running their scripts.
