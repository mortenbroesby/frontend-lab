## Share a preference between tabs

Build a React preference control that updates another tab immediately. You'll learn how browser messages differ from saved state, and how to avoid sending the same update back and forth.

### 1. Start with local state

[Create a demo](#/create) in Modern Web Capabilities. Replace its `index.tsx` with the component below. Keep the generated `main.tsx` and metadata.

```tsx
import { useEffect, useRef, useState } from 'react';
import { Button } from '@lab/ui/button';

export default function Demo() {
  const [compact, setCompact] = useState(false);
  const channel = useRef<BroadcastChannel | null>(null);

  useEffect(() => {
    const connection = new BroadcastChannel('lab-layout-preference');
    channel.current = connection;
    connection.onmessage = (event: MessageEvent<unknown>) => {
      if (typeof event.data === 'boolean') setCompact(event.data);
    };
    return () => {
      channel.current = null;
      connection.close();
    };
  }, []);

  function toggle() {
    const next = !compact;
    setCompact(next);
    channel.current?.postMessage(next);
  }

  return (
    <section>
      <Button aria-pressed={compact} onClick={toggle}>Compact layout</Button>
      <ul style={{ lineHeight: compact ? 1.4 : 2.4 }}>
        <li>One idea</li><li>Another idea</li><li>Your next experiment</li>
      </ul>
    </section>
  );
}
```

Run your generated demo. The button changes the list's spacing. The React state is still the source of what this tab renders.

### 2. Connect another tab

Open the exact same URL in a second tab of the same browser profile. Toggle either button: both lists should update. The channel name identifies the conversation; use your own name if other experiments share the same origin.

`postMessage` sends to other channel instances, not back to the sending instance. That's why `toggle` updates local state itself. The receiving handler only updates state; posting again there would create an echo loop. The type check rejects messages this control doesn't understand.

BroadcastChannel works within the same origin and storage partition. It doesn't connect a phone to a laptop. For that, use [Connect two browsers](#/track/modern-web/devices).

### 3. Add memory, if your idea needs it

Reload one tab: it starts with the default spacing. Messages are events, not a saved history.

To keep the preference, store it in `localStorage` when a local or incoming change arrives, and read it when initialising state. Parse stored values explicitly; handle unavailable storage. The channel delivers live updates while storage supplies the starting value.

Check opening a third tab after a change and reloading an existing one. Decide which update wins if two tabs change the preference together; a simple last-arriving update is enough for this experiment.

### Take it further

Synchronise a colour or a selected document instead. Use a message object with a `type` and validated payload when you introduce more than one kind of event.
