Choose a preference, selected document or draft to synchronise. Decide which values should travel and which should stay local.

### Understand the mechanism

BroadcastChannel exchanges messages within the same origin and storage partition. It doesn't connect separate devices; use [Connect two browsers](#/track/modern-web/devices) for that.

A message isn't saved history. Decide whether a new tab should start fresh, read storage or ask another tab—and what happens when two tabs change a value together.

Follow `postMessage` and the receiving handler in `demos/cross-tab-messaging/index.tsx`, alongside the [BroadcastChannel reference](https://developer.mozilla.org/en-US/docs/Web/API/BroadcastChannel). A channel doesn't receive its own messages. Forwarding received updates can create an echo loop. Preserve message validation and connection cleanup.

### Try your idea

Adapt the demo or use your own app. Test a late join, simultaneous changes or a reload against the behaviour you chose.

If persistence matters, investigate [localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage), including parsing and unavailable storage. It isn't required just to demonstrate messaging.

If nothing arrives, check the origin, browser profile and channel name before changing your state logic.
