## Make something happen on another screen

Choose an interaction: a remote control, shared drawing, reaction—or your own idea. Try <DemoLink id="device-rally">Device Rally</DemoLink> in two browsers, then disconnect and rejoin. What travels between screens, and what stays local?

### Understand the pieces

- **Discovery:** Trystero introduces peers with matching app IDs and room codes through signaling services.
- **Connection:** WebRTC establishes a network path. Discovery doesn't guarantee a connection.
- **Messages:** your app decides what to send and how the receiving screen responds.

A reaction is an event; a selected colour is state. Should a newcomer receive the current value or only future changes? Messages don't automatically provide shared history.

### Find your starting point

Use your own app, adapt the demo or [create an experiment](#/create). For a new Lab workspace, install Device Rally's Trystero version, replacing `your-id`:

```sh
npm install --save-exact trystero@0.27.0 --workspace @lab/demo-your-id
```

Follow one cheer through `demos/device-rally/index.tsx`: `joinRoom` finds the group, `makeAction` defines the channel, and `send` and `onMessage` carry the interaction. Look at peer listeners, message validation and cleanup with `leave` before adapting it.

Use [Trystero's documentation](https://github.com/dmotz/trystero) for the APIs and [MDN's WebRTC guide](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Protocols) for signaling, STUN and TURN.

### Challenge your design

Send in both directions, join after a change, or reconnect. Does each screen have the information it needs? Does one message still produce one update?

Start with two localhost windows, internet access and matching room details. For separate computers, each can run a local copy; a phone visiting your laptop needs trusted HTTPS. Plain LAN HTTP isn't supported by this setup.

Use a unique room code and throwaway data: public signaling and a room name aren't authentication. Restricted networks may block connections; TURN relay setup is outside this guide. Local success doesn't prove another network will work.

For same-browser tabs, [explore BroadcastChannel](#/track/modern-web/tab-settings).
