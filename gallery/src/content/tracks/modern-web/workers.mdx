## Move a calculation off the main thread

Build a small calculator whose work happens in a Web Worker. You'll learn to separate computation from React, send a result back and release the Worker when the page closes.

### 1. Give the Worker one job

[Create a demo](#/create) in Modern Web Capabilities. Add `calculate.worker.ts` beside its `index.tsx`:

```ts
self.onmessage = (event: MessageEvent<unknown>) => {
  const limit = event.data;
  if (!Number.isInteger(limit) || typeof limit !== 'number' || limit < 1 || limit > 50_000_000) {
    self.postMessage({ error: 'Use an integer from 1 to 50,000,000.' });
    return;
  }
  let total = 0;
  for (let i = 1; i <= limit; i++) total += Math.sqrt(i);
  self.postMessage({ total });
};
```

The calculation doesn't access the DOM or React state. That separation is what lets it run on another thread. The limit keeps a mistyped input from starting unbounded work.

### 2. Send work from React

Replace `index.tsx` with this component. Keep the generated entry and metadata.

```tsx
import { useEffect, useRef, useState } from 'react';
import { Button } from '@lab/ui/button';

export default function Demo() {
  const worker = useRef<Worker | null>(null);
  const [busy, setBusy] = useState(false);
  const [result, setResult] = useState('Ready');
  const [taps, setTaps] = useState(0);

  useEffect(() => {
    const instance = new Worker(new URL('./calculate.worker.ts', import.meta.url), { type: 'module' });
    worker.current = instance;
    instance.onmessage = (event: MessageEvent<{ total?: number; error?: string }>) => {
      setResult(event.data.error ?? String(event.data.total));
      setBusy(false);
    };
    instance.onerror = () => {
      setResult('Calculation failed. Reload to try again.');
      setBusy(false);
    };
    return () => {
      worker.current = null;
      instance.terminate();
    };
  }, []);

  return (
    <section>
      <Button disabled={busy} onClick={() => {
        setBusy(true);
        worker.current?.postMessage(50_000_000);
      }}>Calculate</Button>
      <Button onClick={() => setTaps(value => value + 1)}>Tap: {taps}</Button>
      <p role="status">{busy ? 'Working…' : result}</p>
    </section>
  );
}
```

Start your demo and click Calculate, then Tap. The tap count remains interactive while the Worker calculates. On a fast machine the calculation may finish before you tap; use browser CPU throttling or inspect a Performance recording instead of increasing the bound indefinitely.

### 3. Understand the tradeoff

Vite recognises the `new Worker(new URL(...))` expression and builds a separate module. Messages cross the thread boundary; ordinary objects are cloned. A Worker can improve responsiveness without making the calculation itself faster.

Temporarily run the same bounded loop directly in the Calculate handler and compare responsiveness. Restore the Worker afterwards. Keep the input identical so you're comparing where work runs, not different calculations.

### Take it further

- Add Cancel with `terminate()`, then create a fresh Worker for the next run. A busy synchronous loop cannot process a cancel message until it finishes.
- Add request IDs if you allow overlapping jobs, so old results cannot replace newer ones.
- Try image or data processing. Measure transfer costs as well as calculation time.
