# Ideas to explore

Explore capabilities beyond everyday page UI. Pick one question, build a small interaction and see what the browser makes possible.

## Devices talking to each other

Turn a phone into a controller, send reactions between laptops or build a shared drawing surface. Investigate how peers find each other, exchange messages and recover after a connection drops.

Start with one message between two browsers. Then compare peer-to-peer communication with a server-mediated connection. WebRTC still needs signaling; WebSockets need a server. Choose the simplest arrangement that fits your experiment.

Read: [MDN’s WebRTC guide](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API) and [WebSockets overview](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API).

## Interactive graphics

Make information respond to a pointer, a slider or a selection. Try a dependency map, a small simulation or an animated explanation. SVG, Canvas and D3 offer different ways to represent and manipulate a scene.

Start with a few shapes and one interaction. Add relationships or motion, then consider how somebody could use it with a keyboard or reduced motion.

Read: [Canvas tutorial](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial) and [getting started with D3](https://d3js.org/getting-started).

## Computation without blocking the interface

Move a calculation into a Worker and keep the page responsive while it runs. Explore progress, cancellation and the cost of transferring data. For another direction, investigate where WebAssembly could be useful.

Compare the same bounded calculation on and off the main thread. Does interaction improve? What happens if the input changes before the result arrives? Off-thread work need not finish faster to feel better.

Read: [using Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers) and [WebAssembly concepts](https://developer.mozilla.org/en-US/docs/WebAssembly).

## Browser-native experiences

Explore View Transitions or another browser API you rarely use. Try animating a change of view, working with local files or using a device capability in a small React interface.

Start with one visible behaviour. Investigate browser support, permissions and a useful fallback before combining APIs.

Read: [View Transition API](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API). Follow the related API references to choose your next experiment.
