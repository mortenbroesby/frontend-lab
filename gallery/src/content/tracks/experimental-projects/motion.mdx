## Give movement a purpose

What should someone understand: an item moved, a panel opened, an action succeeded? Choose a working interaction and give movement a job.

Compare Still, Motion and Motion + Lottie in <DemoLink id="motion-with-purpose">Motion with purpose</DemoLink>. Vary the duration. When does movement clarify the change, and when does it distract?

The demo saves only local React state. Replay repeats the illustration, not the save. It makes no network request or performance measurement.

### Choose a technique

| Need | Starting point |
| --- | --- |
| Colour, focus or opacity transitions | CSS |
| React elements entering, leaving or changing layout | Motion |
| An authored illustration with a timeline | Lottie |

SVG describes shapes; Lottie JSON adds a timeline and may reference images or fonts. You don't need both libraries.

Explore [Motion's layout](https://motion.dev/docs/react-layout-animations), [SVG](https://motion.dev/docs/react-svg-animation) or [exit animation](https://motion.dev/docs/react-animate-presence) guides according to your interaction. Compare one parameter at a time: duration sets how long; [easing](https://motion.dev/docs/react-transitions) sets how progress changes.

### Follow the reference

After [local setup](#/guide/setup):

```sh
npm run dev --workspace @lab/demo-motion-with-purpose
```

In `demos/motion-with-purpose/`, `index.tsx` connects state and transitions; `SaveSeal.tsx` owns the Lottie player and cleanup. Follow a save: committing data must remain independent of animation completion. Networked confirmation should follow the real operation's outcome.

Download the demo's animation to explore `save-seal.json`. `ASSET.md` documents its hand-authored, CC0 origin; it isn't an After Effects export. Its final frame works without movement.

For replacement artwork, check license, assets and [player compatibility](https://lottiefiles.com/supported-features). The demo's lightweight SVG player supports shape-only artwork. [Lottie Web](https://github.com/airbnb/lottie-web) documents playback and authoring routes, including Bodymovin. Test in the actual player and release it on unmount.

### Challenge the treatment

Interrupt or repeat the action. Enable Reduce Motion. Remove or delay the artwork. Can someone still use the controls and understand the result?

Keep layout space reserved, focus useful and confirmation finite. Decorative artwork shouldn't duplicate accessible text. Read [Motion's reduced-motion guidance](https://motion.dev/docs/react-accessibility). Keeping an interaction still is a valid result.
