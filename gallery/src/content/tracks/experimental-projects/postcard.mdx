## Draw with rules

Invent a visual rule and see what it produces. You could explore a grid with deliberate irregularities, imaginary coral, lettering or a composition of your own. Decide what gives the image its character before adding controls.

Try <DemoLink id="generative-postcard">Generative postcard</DemoLink>. Keep a seed while changing a parameter, then change the seed. Which features belong to the rule and which come from chance?

### Choose your constraints

A generative image is more than random positions. Shape, repetition, spacing, palette and empty space all affect the result.

Pick one relationship to explore: size might depend on distance, colour on direction, or spacing on an underlying grid. You choose the relationship and the shapes. A few marks are enough to see whether an idea is interesting.

### Make chance repeatable

A seeded pseudo-random generator produces the same sequence for the same seed and algorithm. That lets you compare rule changes without changing every random choice too.

Decide which properties should vary and which should remain stable. Reordering calls to the generator changes which values reach which properties. Calling `Math.random()` while rendering makes it harder to reproduce a composition.

Reproducibility needs the rules and parameters as well as the seed. This kind of randomness is for artwork, not secrets or security tokens.

### Explore the reference

Use your own app, [create an experiment](#/create) or adapt the demo. In `demos/generative-postcard/`, `art.ts` contains generation rules and `index.tsx` connects those rules to SVG, controls and export. Follow one generated value to the shape it affects.

The [SVG tutorial](https://developer.mozilla.org/en-US/docs/Web/SVG/Tutorial) explains shapes, coordinates and transforms. Choose the part your idea needs; you don't have to recreate the demo's dots or spiral.

Keep one composition stable while changing a rule. Then try several seeds: does the rule produce a family of interesting images, or only one lucky result?

### Decide what to keep

If exporting matters, investigate how the demo turns SVG into a file using [XMLSerializer](https://developer.mozilla.org/en-US/docs/Web/API/XMLSerializer). Consider what the file needs outside the app: explicit styling, referenced assets and its own dimensions.

Open an exported file independently. Does it still look right without the page's CSS? Can you recreate it from the saved seed and parameters? Release temporary object URLs when they are no longer needed.

Export is optional. Your experiment might instead be an interactive drawing, a collection of variations or a rule that responds to input. Let the visual idea determine the next feature.
