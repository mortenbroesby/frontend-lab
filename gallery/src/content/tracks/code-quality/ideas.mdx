<div className="track-directions">
<section id="dependencies" tabIndex={-1}>
<h3>Explain a dependency before removing it</h3>
<p>Pick a package you don't recognise. The external <a href="https://docs.npmjs.com/cli/v11/commands/npm-explain/">npm explain documentation ↗</a> shows how to trace why it is installed. Check imports, scripts and configuration too: apparent non-use can be misleading.</p>
<p><strong>Start small:</strong> run <code>npm explain react</code> in the Lab and follow one chain to a real consumer. An old version alone is not evidence that a package should be replaced.</p>
<DemoLink id="dependency-map">Explore Dependency Ripple →</DemoLink> · <a href="#/track/code-quality/dependencies">Trace a dependency's reach →</a>
</section>
<section id="clarity" tabIndex={-1}>
<h3>Make one change easier to reason about</h3>
<p>Pick a function with too many decisions or an import that crosses an unexpected boundary. The external <a href="https://eslint.org/docs/latest/rules/complexity">ESLint complexity examples ↗</a> can help explain a metric; a lower score isn't the goal.</p>
<p><strong>Start small:</strong> name the inputs, outcome and one confusing branch. Try a clearer name or early return, then run the relevant check. For unexpected coupling, trace the import before introducing a rule.</p>
<a href="#/track/code-quality/fallow">Investigate with Fallow →</a> · <a href="#/track/code-quality/architecture">Protect an architecture boundary →</a>
</section>
<section id="confidence" tabIndex={-1}>
<h3>Find out whether green tests mean what you think</h3>
<p>Choose one observable behavior and the assertion that protects it. Use your existing test runner; the external <a href="https://nodejs.org/docs/latest-v24.x/api/test.html">Node test runner documentation ↗</a> explains the one used for the Lab's logic tests.</p>
<p><strong>Start small:</strong> predict a mistake the test should catch. Make that reversible change on your branch and run the test. Restore the implementation before strengthening an assertion.</p>
<a href="#/track/code-quality/test-confidence">Find a missing test →</a>
</section>
