# Getting started

**You need:** an accessible codebase, editor and its usual tools. Use your own repository or the working `gallery/` as a small fallback. Do not upload private source to an external service without permission.

## Start with the fallback

After [local setup](#/guide/setup), run from the repository root:

```sh
npm ls --depth=0
npm explain d3-force
```

This uses Node 24.x and npm. Expect a dependency list and an explanation of which workspace requires D3. None of these outputs proves that a dependency is unused or that a codebase has no problems.

## Try automated analysis

From the repository root, run `npm run analyze`. Fallow is installed by `npm ci`; no separate account or global installation is needed. Read the [Fallow walkthrough](#/track/code-quality/fallow) for focused commands, expected findings and how to interpret an exit code of 1. You can investigate without creating a new demo.

## Choose another route

For architecture, run `npm run check:architecture` and inspect one rule in `.dependency-cruiser.cjs`. The **Demos** tab explains a real boundary investigation using dependency-cruiser, which is already installed.

For dependency health, follow `d3-force` from `demos/constellation/package.json` to its imports in `index.tsx`. For test confidence, follow `index.tsx` → `compute.worker.ts` → `compute.ts` under `demos/workers/`.

Pick one question, trace the evidence and decide whether to keep the code or change it. You do not need a new demo or a report.

**Use your own repository:** replace these commands with its documented setup/checks. No need to copy the gallery into it. If you choose automated analysis, record the tool/version/configuration and validate a few findings manually; an outdated dependency is not automatically harmful.
