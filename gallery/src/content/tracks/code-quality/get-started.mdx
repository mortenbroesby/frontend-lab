# Getting started

**You need:** a codebase, editor and its usual tools. Use your repository or `gallery/`. Never upload private source externally without permission.

## Start with the fallback

After [local setup](#/guide/setup), run from the repository root:

```sh
npm ls --depth=0
npm explain d3-force
```

With Node 24 and npm, these list dependencies and explain which workspace needs D3. Neither proves a dependency unused or a codebase sound.

## Try automated analysis

Run `npm run analyze` from the root. `npm ci` installs Fallow; no account or global install needed. The [Fallow walkthrough](#/track/code-quality/fallow) covers focused commands, findings and exit code 1.

## Choose another route

For architecture, run `npm run check:architecture` and inspect `.dependency-cruiser.cjs`. The **Demos** tab walks through a boundary investigation.

For dependency health, follow `d3-force` from `demos/constellation/package.json` to its imports in `index.tsx`. For test confidence, follow `index.tsx` → `compute.worker.ts` → `compute.ts` under `demos/workers/`.

Trace one question and decide whether to change the code. No new demo or report needed.

**Your own repository:** use its setup/checks. Record analysis tools, versions and configuration; verify findings manually. An outdated dependency is not automatically harmful.
