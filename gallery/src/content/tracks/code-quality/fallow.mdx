## Investigate with Fallow

Choose a question about your code, investigate a finding and make one justified improvement. Keeping code after understanding it is a valid result.

Fallow is installed in the Lab. In another npm project:

```sh
npm install --save-dev --save-exact fallow
```

Use your existing package manager. Start with discovery rather than copying the Lab's configuration.

### Choose a question

| Question | Command |
| --- | --- |
| What's unused? | `npx fallow dead-code` |
| What logic is duplicated? | `npx fallow dupes` |
| What's hard to reason about? | `npx fallow health` |
| Where do imports form a cycle? | `npx fallow architecture` |

These commands don't edit code. Exit 1 can indicate findings above a threshold; inspect the result. Use your installed version's `--help` when documentation differs.

### Verify before changing

Follow callers near a finding you understand:

- **Unused:** could a route, generated code, dynamic import or external consumer use it?
- **Duplicated:** should the copies change together?
- **Complex:** would a clearer responsibility help, or merely move the score?
- **Cyclic:** which module should own the shared responsibility?

For surprising results, inspect discovery:

```sh
npx fallow list --entry-points --plugins --workspaces
```

Represent missing entries or dynamic consumers narrowly rather than ignoring findings wholesale. Review any configuration generated by `npx fallow init`.

No suitable finding? Trace a dependency, such as `npx fallow dead-code --trace-dependency d3-force` in the Lab. An empty trace doesn't prove it is removable.

### Check your decision

After an edit, rerun the scan and relevant tests, type check or build. A lower score doesn't establish correctness; coverage-related estimates aren't measured coverage without supplied data.

Before team adoption, validate discovery and findings before adding blocking policies or baselines.

Read [quick start](https://fallow.tools/docs/quickstart/), [configuration](https://fallow.tools/docs/configuration/), [finding explanations](https://fallow.tools/docs/explanations/dead-code/) and [adoption guidance](https://fallow.tools/docs/adoption/).
