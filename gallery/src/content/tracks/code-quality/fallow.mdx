# Investigate with Fallow

Pick a question, run analysis and verify a finding in this repository. The root lockfile pins Fallow 3.43.1 as a development dependency.

## Get a first result

After [local setup](#/guide/setup), run these from the **repository root**:

```sh
npm run analyze -- --version
npm run analyze
```

`analyze` checks unused code, duplication and health. It reads local source and may cache in ignored `.fallow/`; it applies no fixes and needs no account, cloud connection or extension. The gallery explains the investigation; terminal output supplies current evidence.

**Exit codes matter:** completed scans can exit 1 when findings exceed thresholds. Read findings and gate messages; missing binaries, invalid configuration and parse errors need separate investigation. Analysis runs outside `npm run check`; hooks and CI gate new findings as described below.

## Set up agents and commit checks

After `npm ci`, check `npm run fallow:status`. Install missing hooks once per clone with `npm run fallow:hooks`; the official installer refuses to overwrite hooks. Your terminal and Git client need Node/npm.

**Codex and Copilot CLI** share root `AGENTS.md` and `.agents/skills/fallow`, which links the pinned dependency’s official instructions. Do not duplicate the task map or add per-agent hooks.

Agents use the same CLI: `npm run analyze` and `npm run analyze:changes`. No MCP server needed.

The **pre-commit hook** runs `fallow audit --staged` against HEAD for agent and manual commits. It blocks new findings; existing findings stay visible without blocking unrelated changes. Inspect failures with `npm run analyze:changes -- --staged`. Agents must run `npm run analyze:changes` before pushing; **no automatic pre-push or per-agent hook exists**. CI compares PRs with their base SHA and main pushes with the previous remote SHA.

Hooks are local, not branch protection. Without Fallow, the hook warns and skips; verify enforcement with the status command. When updating, retain the CLI/shared skill. Avoid `fallow agent install`, which regenerates a larger harness-specific integration.

References: [official Git hooks](https://fallow.tools/docs/cli/hooks/), [Copilot shared skills](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills).

## Choose a lens

| Root command | Question |
| --- | --- |
| `npm run analyze:dead-code` | Which files, exports or dependencies appear unused? |
| `npm run analyze:dupes` | Where is code repeated? |
| `npm run analyze:health` | Which functions deserve a closer look for complexity? |
| `npm run analyze:architecture` | Are there import cycles or configured boundary violations? |
| `npm run analyze -- list --entry-points --plugins --workspaces` | What does the tool think this project contains? |

Pass options after `--`: `npm run analyze:health -- --report-only` gives advisory results. For JSON without npm’s banner, create `.fallow/` if needed, then run `npm run --silent analyze:dead-code -- --format json --output-file .fallow/dead-code.json`.

## Worked investigation: why is this dependency here?

Trace a real dependency from the repository root:

```sh
npm run analyze:dead-code -- --trace-dependency d3-force
```

Follow the result into `demos/constellation/index.tsx`. Compare imports with uses. What does the dependency provide, and what would replacing it cost? Keeping it can be justified.

Before trusting an unused-code finding, check discovery includes gallery metadata, demo HTML entries and Worker modules.

## Worked investigation: complexity is a clue

Run `npm run analyze:health` and inspect a finding. For example, examine routes and JSX conditions in `gallery/src/app/App.tsx`. Would extracting a view clarify intent or just move branches?

Fallow receives no coverage file: its CRAP/risk score is **not measured test coverage**. Tests cover selected logic; high scores do not prove defects. Preserve routes and error handling during refactors, and check changed behaviour. Leaving code alone can be reasonable.

## How this repository is configured

- `.fallowrc.json` declares workspace patterns, TypeScript app entries and the existing thresholds. Built-in discovery adds package exports, Vite, tests, generators and Workers. Recheck it when entries move.
- Root scripts scan the current workspace outside Turbo’s cache. No wrapper or per-demo configuration.
- `.baselines/` records reviewed findings. Run `npm run analyze:baseline` to compare the whole repo; `npm run analyze:health` still shows existing findings. Read the baseline README before refreshing.
- No Fallow boundary rules or rule packs. `npm run check:architecture` separately enforces dependency-cruiser rules; a clean Fallow result says nothing about that policy.
- `.fallow/` holds ignored generated data. Never commit caches or machine-specific reports.

If discovery misses an entry, inspect it before adding a narrow `entry` pattern in `.fallowrc.json`. Do not mark every file as an entry or ignore directories to clear findings. Understand changes before applying automatic fixes.

Keep sensitive source and reports within the repository's permitted audience.
