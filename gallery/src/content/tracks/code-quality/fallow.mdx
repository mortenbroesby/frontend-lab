## Investigate with Fallow

**An export is marked unused. Would you delete it?** Perhaps nothing calls it. Perhaps the scanner missed the route that does. The useful part is finding out.

### Try it: would you delete this?

Imagine a report flags `formatPrice` in `checkout/format.ts`. A text search finds no imports. Before removing it, what would you check?

<details>
<summary>Compare your reasoning</summary>

A private helper with no callers may be dead code. An export from a published package may have consumers outside the repository. A dynamically loaded route may be missing from discovery. The same report can lead to different decisions; the report alone doesn't settle it.

</details>

### Find a real lead

Fallow is installed in the Lab. In another npm project, use `npm install --save-dev --save-exact fallow`, or your package manager's equivalent.

| Your question | Read-only command | Evidence to look for |
| --- | --- | --- |
| What's unused? | `npx fallow dead-code` | Callers, public exports, dynamic entry points |
| What's duplicated? | `npx fallow dupes` | Should these copies change together? |
| What's hard to follow? | `npx fallow health` | Mixed responsibilities, not just a score |
| What forms a cycle? | `npx fallow architecture` | Which module should own the shared responsibility? |

Pick one finding you understand. If discovery looks surprising, inspect it:

```sh
npx fallow list --entry-points --plugins --workspaces
```

Review any configuration generated by `npx fallow init`. Represent missing consumers narrowly; don't ignore a whole category to silence one false positive. Exit 1 can mean findings exceeded a threshold—read the output and your installed version's `--help`.

No useful finding? Trace a known dependency with `npx fallow dead-code --trace-dependency d3-force` in the Lab. An empty trace isn't proof that it can go.

### Make one defensible change

Remove confirmed dead code, correct discovery or simplify a responsibility. Rerun the scan and relevant tests, type check or build. **Done means the evidence supports your decision**, even if that decision is to keep the code.

Try the same investigation in your own repository before adopting blocking policies or baselines. A lower score isn't proof of correctness.
