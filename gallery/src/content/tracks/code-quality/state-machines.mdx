## What is a state machine?

**Press Back twice. Why does the same button do two different things?** Open <DemoLink id="canvas-tv">Remote / Canvas TV</DemoLink>, start a title and try it: the first Back hides the controls; the second returns to browsing.

A **state machine** names the modes an interaction can be in and the events that move it between them. The current mode determines what an input means.

<div className="guide-flow" role="group" aria-label="TV playback transitions">
  <div><strong>Browsing → Controls visible</strong><span>OK starts a title</span></div>
  <span aria-hidden="true">↓</span>
  <div><strong>Controls visible → Watching without controls</strong><span>Back or Up hides the overlay</span></div>
  <span aria-hidden="true">↓</span>
  <div><strong>Watching → Browsing or Controls visible</strong><span>Back returns to browsing; OK or Down reveals controls</span></div>
</div>

### Predict the next action

Hide the controls, then press Right. Nothing changes. Reveal them and press Right again: now it selects a subtitle option. OK applies that option without leaving the controls state.

**State is the mode; data records the details.** Title and subtitle selections don't need a separate state for every combination. Replacing `playing` and `controlsVisible` with explicit modes makes “browsing with playback controls visible” impossible to represent.

For another interactive example, try [Stately's stopwatch](https://codesandbox.io/p/sandbox/github/statelyai/xstate/tree/main/examples/stopwatch). Or choose **Click to interact** in [Stately's introduction](https://stately.ai/docs/state-machines-and-statecharts). Those examples use full XState; this TV uses its compact FSM API.

### Read the working machine

After [local setup](#/guide/setup), run:

```sh
npm run dev --workspace @lab/demo-canvas-tv
```

Open `demos/canvas-tv/playback-machine.ts`. It uses **`xstate/fsm`**, XState's compact finite-state-machine entry point. This demo pins **XState 6.0.0-beta.3**: the API is beta and may change. See the [compact FSM documentation](https://stately.ai/docs/xstate/v6/fsm) and [stable XState documentation](https://stately.ai/docs/xstate/v5/quick-start) when choosing for another project.

One transition reads:

```ts
browsing: { on: { Enter: { target: 'controls' } } }
```

In `navigation.ts`, `playbackMachine.transition(snapshot, event)` calculates the next snapshot. React keeps it in the existing reducer. Catalogue movement and subtitle selection remain ordinary functions; drawing and animation stay outside the machine. Keyboard, touch remote and phone commands reach the same navigation function.

### Explore a different rule

Choose one change, or bring an interaction from your own application:

- **Change what Back means.** Should it always leave playback? Sketch the affected arrows before editing. What happens to someone who only wanted the controls out of the way?
- **Add a paused mode.** Which inputs should resume, show controls or leave? Decide whether pausing and control visibility are independent before multiplying states.
- **Investigate a confusing form or dialog.** List its modes and events. Look for combinations of flags that should never coexist. Would explicit states make those rules easier to explain?

Follow one sequence through the model, then try it in the interface. `navigation.test.ts` contains small checks for returning to the same title, hiding controls and keeping subtitles. Change a rule deliberately and see which expectation needs reconsidering.

### Draw first, add machinery when useful

Use [Stately's editor](https://stately.ai/editor) to sketch states and labelled arrows. Compare the sketch with the working transition table; this demo does not connect a live inspector.

The compact FSM suits these flat, synchronous modes. For nested states, timers, effects or communicating actors, explore [full XState](https://stately.ai/docs). Its richer runtime also brings more concepts. A single open/closed toggle may be clearer as ordinary React state; choose a machine when making the allowed behaviour explicit helps you reason about it.
