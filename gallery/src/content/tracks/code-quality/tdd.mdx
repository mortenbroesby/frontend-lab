## Try test-driven development

**Describe one thing the code should do. Make it work. Then tidy up.** That's the TDD cycle.

<div className="tdd-cycle" role="group" aria-label="The test-driven development cycle">
  <div className="tdd-red"><strong>1 · Red</strong><span>Write a failing test</span></div>
  <span aria-hidden="true">→</span>
  <div className="tdd-green"><strong>2 · Green</strong><span>Make it pass</span></div>
  <span aria-hidden="true">→</span>
  <div><strong>3 · Refactor</strong><span>Tidy up; keep it passing</span></div>
</div>

Repeat for the next behaviour. You don't need to design the whole feature first.

### Try it: a carousel's Next button

We’ll write a function that selects the next item, wrapping back to the start:

<div className="tdd-selection" role="img" aria-label="Next moves from item zero to one, then two, then back to zero">
  <span>0</span><b aria-hidden="true">→</b><span>1</span><b aria-hidden="true">→</b><span>2</span><b aria-hidden="true">↩</b><span>0</span>
</div>

Use [Node 24 and local setup](#/guide/setup), then [create a demo](#/create) or use one you own. Add the files below beside its `index.tsx`. No extra dependencies.

### 1. Write a test that fails

Create `selection.test.ts`:

```ts
import assert from 'node:assert/strict';
import test from 'node:test';
import { nextIndex } from './selection.ts';

test('next moves to the following item', () => {
  assert.equal(nextIndex(0, 3), 1);
});
```

Create `selection.ts` with this unfinished implementation:

```ts
export function nextIndex(current: number, count: number): number {
  return current;
}
```

Run from the repository root. Replace `your-id` with your demo's folder ID:

```sh
node --test demos/your-id/selection.test.ts
```

**Expected: fail — got 0, wanted 1.** A missing file or syntax error isn't the failure we're looking for.

### 2. Make it pass

Change `return current` to `return current + 1`. Run again.

**Expected: pass.** Now add the next test to `selection.test.ts`:

```ts
test('next wraps from the last item to the first', () => {
  assert.equal(nextIndex(2, 3), 0);
});
```

Run it before changing the implementation. **Expected: fail — got 3, wanted 0.** Add wrapping, then run both tests.

<details>
<summary>Show one possible solution</summary>

```ts
export function nextIndex(current: number, count: number): number {
  if (current === count - 1) return 0;
  return current + 1;
}
```

</details>

### 3. Tidy up, keeping both tests green

Could a name or expression be clearer? Try one change and rerun. Keep the existing expectations. If the code is already clear, move on.

**Done:** both tests pass, and you can change the implementation without changing what Next means.

### Make it your own

Try a one-item carousel, a Previous button or a rule from your own feature. Write one example before implementing it. This exercise assumes a non-empty list and a valid index; decide what an empty list should mean before supporting it.

Function tests don't prove the button works. For a React interaction, use your project's component test setup to click Next and check the selected item. For exploratory visuals, sketch first and test rules once they're clear.
