# Investigations to explore

These written investigations use local commands, not live browser analysis. **A test gap, investigated** traces one confidence improvement; **Investigate with Fallow** uses current terminal output.

## A test gap, investigated

- **Try:** [Read the investigation](#/demo/quality), then run `npm test --workspace @lab/demo-workers` from the repository root.
- **Change:** Add an input to `demos/workers/compute.test.ts` with an independently checked expected value.
- **Observe:** Does it cover a new boundary? A pass supports that case, not all inputs.

## Investigate with Fallow

- **Try:** [Open the walkthrough](#/demo/fallow) and run `npm run analyze:dead-code` locally after setup.
- **Change:** Inspect callers before making a warranted cleanup. No findings is valid.
- **Observe:** Rerun the analysis and relevant checks. Did the finding disappear without changing intended behaviour?

Stretch: investigate a complexity finding.

## Inspect an architecture boundary

After local setup, run from the repository root:

```sh
npm run check:architecture
```

This runs dependency-cruiser. Find `demos-stay-independent` in `.dependency-cruiser.cjs`: demos cannot import each other’s implementations. Trace `demos/workers/index.tsx` imports: which are local, and which are shared?

Compare source imports with the dependency map’s package edges. A passing check means no configured violations in the inspected graph, not a sound architecture.

Explain what one rule prevents. Would it protect an agreed boundary in your own codebase?

Read: [dependency-cruiser rule reference](https://github.com/sverweij/dependency-cruiser/blob/main/doc/rules-reference.md).
