# Lightweight bootstrap plan

No runnable starter or technical exercises are implemented. This directory records the approach; it is not a required entry point for participants.

## Minimal preparation first

The four agreed tracks can begin with a browser example, an existing codebase, an established workflow or a participant's own project. Start by checking access and useful documentation, not by building four exercises. B needs a real or suitable sample codebase, not an intentionally broken app; C starts from actual friction.

Consider one optional **Vite + React + TypeScript** starter for people who want a fresh UI application. First establish demand and inspect an existing minimal template. Participants remain free to use their own repositories, tools and preferred technologies; React is not required for every experiment.

## If a starter is later agreed

- Keep one small independent example with a visible first interaction and minimal dependencies.
- Agree and pin compatible runtime/tool versions, choose a package manager and commit its lockfile.
- Document only implemented install/start commands and verify them from a clean checkout.
- Provide a short route to adapting the example and recording findings, without a prescribed solution.
- Avoid shared application architecture, monorepo orchestration, containers, cloud requirements and optional toolchains installed for everyone.

WebAssembly and real-time communication may need extra setup depending on the chosen experiment. Participants can use a documented minimal example or choose a simpler capability; no organiser-provided backend or specialist toolchain is promised.

## Readiness evidence

For any starter actually added, record the tested environment, exact commands, expected behaviour and setup blockers. Try it with another participant. Select and check a public sample fallback for B separately if useful; do not manufacture technical debt to create an exercise.

The current task is planning only. Next decide whether this optional starter materially reduces friction, then implement only that agreed scope. See [preparation](../planning/preparation.md) for the remaining gaps.
